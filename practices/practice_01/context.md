## Context Pack для первого рабочего сценария

### Факты и правила

- Вход: только diff учебного PR (`TRAINING_PR.diff`)
- Результат: краткое описание, до трёх рисков со ссылкой на файл/строку и доказательством, список проверок
- Решение принимает человек; помощник не может approve/merge или менять код

### Формат входа и результата

- Вход: текстовый unified diff
- Выход: структурированный текст с: 1) описанием изменения; 2) максимум 3 риска: файл, строка(и), причина и как воспроизвести; 3) список проверок

### Ограничения и запрещённые действия

- Запрещено: модифицировать код, выполнять команды, делать merge/approve
- Нельзя утверждать без ссылки на diff или воспроизводимой проверки

### Хороший пример

app/api.py, create_review — обращение payload["diff"] вызывает KeyError, если в теле запроса нет поля diff. Проверка: отправить POST /api/reviews с пустым JSON‑объектом и проверить ответ сервиса.

### Плохой пример

Код можно улучшить. Добавьте тесты и обработку ошибок.
### Что пока неизвестно

- Конкретный runtime сервиса и окружение для проверок (локально, CI)
- Политика обработки ошибок API
