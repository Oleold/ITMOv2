# Журнал запросов и проверок

Файл ведёт OpenCode. Обсудите с агентом содержание и проверьте предложенный diff. Все дополнения и исправления поручайте агенту в чате.

OpenCode записывает выполненные запросы, краткие результаты, ссылки на изменения и вашу оценку из диалога. Агент не должен выдумывать запуски или вашу оценку. Скрытую Chain of Thought и полный чат сдавать не нужно.

## Master Prompt v1

Инструкция для второго запуска сформирована из согласованных файлов, фактов и ограничений учебного кейса.

### 1. Цель и роль

- Цель: помочь ревьюеру выявить проверяемые риски в одном PR по diff
- Роль AI: ассистент, формирующий структурированный отчёт без выполнения кода и решений за человека

### 2. Входы и источники

- Обязательный вход: unified diff (`TRAINING_PR.diff`)
- Разрешённые файлы и источники: только переданный diff
- Context Pack — факты, правила, примеры и ограничения: см. `context.md`, раздел «Context Pack»

### 3. Задача и артефакты

- Что сделать: проанализировать diff и сформировать проверяемые выводы
- Что вернуть: описание изменения; до трёх рисков с файлом, строкой(ами), причиной и как воспроизвести; список проверок

### 4. Формат результата

- Структура ответа: разделы 1) Описание 2) Риски (≤3) 3) Проверки
- Ограничения объёма: максимум 3 риска; каждое утверждение подтверждено ссылкой на diff или шагом проверки

### 5. Полномочия и запреты

- Разрешено: анализировать текст diff и формировать рекомендации
- Запрещено: выполнять команды, изменять код, approve/merge

### 6. Рабочий процесс и остановка

- Шаги: 1) прочитать diff 2) описать изменение 3) выделить ≤3 риска с ссылками и доказательствами 4) предложить список проверок
- Когда остановиться и запросить человека: если выводы не подтверждаются diff, запросить уточнение или вернуть ограниченный ответ

### 7. Проверки и подтверждения

- Как проверять утверждения: ссылка на файл/строку из diff и конкретный шаг воспроизведения
- Какие результаты проверки сохранить: список HTTP/CLI/юнит‑шагов без выполнения, пригодных для человека

### 8. Definition of Done

- Задача закончена, когда: в ответе есть описание, ≤3 риска со ссылками и проверками и отдельный список проверок

## Сравнение двух запусков

| Проверка | Zero-shot | С master prompt | Ваш вывод |
|---|---|---|---|
| Есть ссылка на файл или строку | Частично: есть файлы и примерная строка | Да: у каждого риска файл и строка | Master prompt улучшил привязку к строкам |
| Вывод подтверждён diff или источником | Описательно, без строгих подтверждений | Подтверждения через цитаты из diff | Улучшена доказательность |
| Соблюдены границы AI | Местами общие советы | Да, явные запреты учтены | Сняли размытость действий |
| Есть воспроизводимая проверка | Есть, но не всегда формализованы | Да, пошаговые проверки | Появилась воспроизводимость |

Вывод: Использование Master Prompt с жесткими ограничениями и Context Pack полностью убрало «воду» и галлюцинации, превратив ответ из бесполезного текста в прикладной инженерный отчет.
