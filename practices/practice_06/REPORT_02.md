# Отчёт 2. Проверка исправлений и регрессионных тестов

Ниже зафиксировано состояние после ремедиации. По каждому риску указаны изменения в коде (`lab/service.py`), защита на уровне логики, а также соответствующие регрессионные тесты (`lab/test_service.py`). В конце приведён статус выполнения всего набора тестов.

1) SQL Injection устранён
- Изменения:
  - Вспомогательный метод `rows` теперь принимает параметры и использует параметризованные запросы: `rows(query, params=())` → `self.db.execute(query, params)` (service.py:39–40).
  - `/profile` игнорирует внешний `id` и возвращает профиль только по `session["id"]`: `SELECT ... WHERE id = ?` (service.py:87–88).
  - `/search` применяет параметризацию LIKE: `name LIKE ?` с шаблоном `%q%` (service.py:89–90).
  - `/assistant/context` читает заказ по параметру с `?`: `SELECT * FROM orders WHERE id = ?` (service.py:115–116).
- Регрессионные тесты: `test_sqli_prevented` подтверждает отсутствие влияния инъекций в `/profile` и корректную работу `/search` с кавычками.

2) Broken Access Control (BAC) устранён
- Изменения:
  - Убрано доверие к заголовку `X-Role`. Доступ к экспорту профилей теперь строго по роли из серверной сессии: `session["role"] == "staff"` (service.py:102–105).
- Регрессионные тесты: `test_staff_can_export_with_staff_session` подтверждает, что экспорт доступен только сессии сотрудника.

3) Mass Assignment устранён
- Изменения:
  - Цена заказа теперь берётся исключительно из серверного каталога `self.products`; любое клиентское поле `price` игнорируется (service.py:94–101, особенно 97–101).
- Регрессионные тесты: `test_mass_assignment_prevented` подтверждает, что при передаче `price` клиентом сохраняется каталожная цена.

4) Path Traversal устранён
- Изменения:
  - Для `/files` запрещены `..` и абсолютные пути; имя пользователя также валидируется (service.py:106–114, особенно 109–113).
  - Применена изоляция: доступ разрешён только в директорию пользователя `files/<username>/`, а для чужих пользователей — отказ, кроме роли `staff` (service.py:111–114).
- Регрессионные тесты: `test_path_traversal_prevented` подтверждает запрет на чтение чужих файлов и на выход в `private/...` через `..`.

5) Stored XSS устранён
- Изменения:
  - В `/reviews/view` контент экранируется через `html.escape(..., quote=False)` перед вставкой в HTML (service.py:62–63).
- Регрессионные тесты: `test_xss_escaped` проверяет, что `<script>` преобразуется в безопасные HTML-энтити.

6) LLM Tool Execution ограничен ролями и путями
- Изменения:
  - Для `/assistant/execute` добавлена аутентификация (общая для приватных маршрутов) и авторизация инструментов:
    - `export_profiles` и `delete_tree` доступны только для `session["role"] == "staff"` (service.py:137–145).
    - `read_file` запрещает `..` и абсолютные пути; доступ только к подкаталогу текущего пользователя `files/<username>/...`, если роль не `staff` (service.py:130–136).
- Регрессионные тесты: `test_llm_tools_auth_prevented` подтверждает, что у клиента нет доступа к `export_profiles` и `delete_tree`, а чтение возможно только внутри собственной папки.
