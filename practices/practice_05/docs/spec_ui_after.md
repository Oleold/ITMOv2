# Спецификация UI (Версия ПОСЛЕ согласования)

Цель: реализация «Поиск и фильтрация элементов списка по ключевому слову и статусу» в строгом соответствии с `contract.md`.

## 1. Компоненты интерфейса
- **Поле ввода поиска (query)**:
  - Плейсхолдер: «Поиск по ключевому слову».
  - Поведение: очистка пробелов по краям. Валидация перед отправкой: длина от 2 символов, только буквы, цифры и пробелы.
  - Очистка: кнопка сброса (крестик) очищает ввод и возвращает пользователя на страницу 1.
- **Фильтр статуса (status)**:
  - Опции: «Все» (параметр опускается), «Активен» (`active`), «В архиве` (`archived`), «Черновик» (`draft`).
  - При изменении фильтра страница сбрасывается на 1.
- **Список карточек (items)**:
  - Карточка отображает: `title`, бейдж `status`, `description` (если есть), `createdAt`.
- **Пагинация (meta)**:
  - Кнопки «Назад» и «Вперед», индикатор текущей страницы из общего числа (`meta.page` из `meta.totalPages`).
- **Информеры состояний**:
  - `Loading`: индикатор загрузки списка.
  - `Empty State`: текст «Ничего не найдено» и кнопка «Сбросить фильтры».
  - `Validation Error`: инлайн-ошибка под полем ввода при длине < 2 символов или недопустимых символах.
  - `Server/Network Error`: баннер сверху списка с кнопкой повтора.

## 2. Формат взаимодействия с API (GET /api/items)
- Параметры: `query` (string), `status` (string), `page` (number), `limit` (number, default: 20).
- Формат 200 OK:
  - `data`: массив объектов `{ id, title, status, description, createdAt }`
  - `meta`: `{ page, limit, total, totalPages }`
- Формат 400 Bad Request:
  - `{ code, message, details: [{ field, message }] }`
