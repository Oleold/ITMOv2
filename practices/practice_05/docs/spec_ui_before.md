# Спецификация UI (черновик, SDD)

Цель: реализовать «Поиск и фильтрация элементов списка по ключевому слову и статусу» с клиентской валидацией ввода, отображением состояний и пагинацией. Эта спецификация описывает ожидания до написания кода.

## 1. Экраны и компоненты

Единый экран «Список элементов» с адаптивной вёрсткой.

- Поле ввода поиска
  - Тип: однострочное текстовое поле.
  - Placeholder: «Поиск по ключевому слову».
  - Иконки: лупа слева; крестик сброса справа (появляется при непустом вводе).
  - Подпись/описание ошибки под полем (inline), место зарезервировано.
  - Поведение: trim пробелов на краях, свёртка повторных пробелов в один для запроса.

- Фильтр статуса
  - Тип: выпадающий список (Select) с опциями: «Все», «Активен», «Черновик», «Архив».
  - По умолчанию: «Все».
  - На мобильных — полноэкранный селектор.

- Список карточек
  - Вертикальная лента карточек. Каждая карточка: заголовок, статус, краткое описание, дата обновления, опционально теги.
  - Скелетоны при загрузке (3–10 штук в зависимости от ширины экрана/страницы).

- Пагинация
  - Элементы: «Назад», номера страниц, «Вперёд».
  - Управление доступностью: «Назад» неактивен на первой странице; «Вперёд» неактивен на последней.
  - По умолчанию: 20 элементов на страницу (фиксированно).

- Информеры и ошибки
  - Пустое состояние: иллюстрация/иконка + текст «Ничего не найдено» + подсказка «Измените запрос или фильтры» + кнопка «Сбросить».
  - Баннер ошибок сети/сервера сверху списка (non-blocking), с возможностью «Повторить».

Адаптивность
- Desktop: поиск и фильтр в одной строке; список в 2–3 колонки по сетке карточек, если дизайн допускает; либо одна колонка — согласно текущему дизайну системы.
- Mobile: поиск и фильтр в столбик; список в одну колонку; пагинация упрощается до «Назад/Вперёд» + текущая страница.

Доступность
- Поле поиска с label, aria-invalid при ошибке, описанием ошибки связью aria-describedby.
- Кнопки пагинации имеют aria-label с номером/направлением и disabled-состояния.
- Кнопка «Сбросить» доступна с клавиатуры.

## 2. Действия пользователя

- Ввод текста в поле поиска.
- Подтверждение поиска клавишей Enter или по debounce (см. ниже).
- Очистка поля: иконка крестика или клавиша Esc — очищает ввод, сбрасывает страницу на 1, повторяет запрос.
- Выбор статуса в фильтре — немедленный запрос или после debounce.
- Сброс фильтров: кнопка «Сбросить» возвращает статус = «Все», поиск = пусто, страница = 1.
- Навигация по страницам: клики по номерам/стрелкам обновляют список.

Триггеры запроса
- Debounce 300 мс при изменении поисковой строки и/или статуса (если нет ошибки валидации) и отсутствие активного ввода.
- Немедленный запрос по Enter.
- Всегда сброс страницы на 1 при изменении поисковой строки или статуса.

## 3. Состояния интерфейса

- initial
  - До первого запроса: пустой список, без баннеров, без ошибок.
  - Поля имеют значения по умолчанию: поиск пустой, статус «Все», страница 1.

- loading
  - Блок списка показывает скелетоны карточек.
  - Пагинация недоступна (disabled) до получения ответа.
  - Поле ввода и фильтр остаются активны; повторные запросы отменяют предыдущие.

- success
  - Отображается список карточек и пагинация согласно ответу API.
  - Баннеры ошибок скрыты.

- empty result
  - При успешном ответе с 0 элементами: блок «Ничего не найдено» + «Сбросить».
  - Пагинация скрыта.

- validation error (клиентская)
  - Поле поиска в состоянии ошибки: красная рамка, aria-invalid, текст ошибки под полем.
  - Запросы к API не отправляются до исправления.
  - Пагинация и список отображают предыдущее успешное состояние (или initial), без обновления.

- network error
  - При ошибке сети/таймауте/5xx: баннер ошибки над списком с текстом и кнопкой «Повторить».
  - Список либо показывает предыдущее успешное состояние, либо скелетоны исчезают и показывается баннер + попытка повторить.
  - Повтор «Повторить» инициирует загрузку текущих параметров.

Примечание: Ошибка 4xx с тела ответа, описывающего валидацию, отображается как «ошибка сервера/валидации API» баннером и/или inline, если поле указано (см. раздел 5).

## 4. Валидация на клиенте

Требования
- Минимум 2 символа после trim.
- Запрет спецсимволов: разрешены только буквы (кириллица и латиница), цифры и пробелы.
- Множественные пробелы сворачиваются в один при формировании запроса.

Определение допустимых символов
- Регулярное выражение для проверки: `^[A-Za-zА-Яа-яЁё0-9 ]+$`
  - Пустая строка допускается как валидная для «поиска по всем» (если пользователь очистил поле). Если непустая — должна соответствовать регэкспу и быть длиной ≥ 2.

Ошибки и тексты
- «Введите минимум 2 символа» — если непустой ввод короче 2 символов после trim.
- «Недопустимые символы. Используйте буквы, цифры и пробелы» — при несоответствии регэкспу.

Отображение ошибок
- Ошибка показывается под полем поиска, поле подсвечивается, добавляется aria-invalid.
- Кнопка очистки доступна. Кнопка «Сбросить» снимает ошибку.
- Пока ошибка активна, запросы к API не выполняются.

Примечания
- Допустимый набор символов может быть расширен (например, дефис, подчёркивание) по продуктовой договорённости. В текущем черновике — строго буквы/цифры/пробелы.

## 5. Ожидаемый формат данных от API

Эндпоинт (пример): GET /api/items

Параметры запроса (query)
- q: строка поиска после trim и свёртки пробелов; опционально, пустая — поиск по всем.
- status: одно из [all, active, draft, archived]; по умолчанию all.
- page: номер страницы (целое ≥ 1); по умолчанию 1.
- perPage: размер страницы (целое, по умолчанию 20). Клиент отправляет фиксированное значение 20.

Структура сущности в списке (минимум)
- id: string | number — уникальный идентификатор.
- title: string — заголовок для карточки.
- status: "active" | "draft" | "archived".
- description: string — краткое описание (может быть пустым).
- updatedAt: string — ISO 8601, дата/время последнего обновления.
- createdAt: string — ISO 8601 (опционально для списка).
- tags: string[] (опционально).

Ответ при успехе (200)
- data: массив сущностей указанной структуры.
- pagination:
  - page: number — текущая страница.
  - perPage: number — элементов на страницу.
  - total: number — всего элементов, удовлетворяющих фильтрам.
  - totalPages: number — всего страниц.

Пример (схематично):
```
{
  "data": [
    {"id": 1, "title": "Пример", "status": "active", "description": "...", "updatedAt": "2025-03-01T12:00:00Z"}
  ],
  "pagination": {"page": 1, "perPage": 20, "total": 1, "totalPages": 1}
}
```

Пустой результат (200)
- data: []
- pagination.total = 0, totalPages = 0 или 1 — клиент корректно обрабатывает оба варианта (пагинация скрыта).

Ошибки API
- Формат ошибки (рекомендуется единый):
  - error: { code: string, message: string, details?: { field?: string, reason?: string } | { [field: string]: string } }
- Типовые коды:
  - invalid_query (400) — некорректные параметры (например, слишком короткая строка на сервере) — отображается баннером; если указан field = "q", можно продублировать inline под полем.
  - not_authorized (401/403) — баннер с текстом из message.
  - server_error (5xx) — баннер «Что-то пошло не так. Повторите попытку позже».
- Network error/timeout — клиентское состояние «network error» с кнопкой «Повторить» (без тела ошибки).

## Логика пагинации на клиенте
- При изменении q или status страница сбрасывается в 1.
- При клике «Назад/Вперёд» — изменение page в пределах [1, totalPages].
- Номера страниц рендерятся до разумного окна (например, текущая ±2) на мобильном; полный набор — на desktop.

## Производительность
- Debounce 300 мс на ввод и изменение фильтра.
- Отмена (abort) предыдущего запроса при новых параметрах.

## Телеметрия (опционально)
- События: SearchSubmitted (q_length, status), PageChanged (page), FilterChanged (status), ErrorShown (type).

## Тексты (RU)
- Placeholder: «Поиск по ключевому слову»
- Ошибка min length: «Введите минимум 2 символа»
- Ошибка недопустимые символы: «Недопустимые символы. Используйте буквы, цифры и пробелы»
- Пусто: «Ничего не найдено»
- Подсказка пусто: «Измените запрос или фильтры»
- Кнопки: «Сбросить», «Назад», «Вперёд», «Повторить»
