# Согласованный контракт взаимодействия (UI & Logic)

## 1. Запрос GET /api/items
Параметры строки запроса (Query Parameters):
- query (string, optional): подстрока поиска по полю title (регистронезависимо). Допустимы буквы, цифры и пробелы, длина от 2 до 200 символов. Если пусто — поиск по всем.
- status (string, optional): фильтр по статусу. Допустимые значения: active, archived, draft. Если выбрано "Все", параметр не передается.
- page (integer, optional, default: 1): номер страницы (>= 1).
- limit (integer, optional, default: 20): элементов на странице (от 1 до 100).

## 2. Успешный ответ (200 OK)
Структура JSON:
{
  "data": [
    {
      "id": "5f1d7b3e-9c2b-4b0e-9c08-2b4f64f2f111",
      "title": "Документ проекта",
      "status": "active",
      "description": "Краткое описание задачи",
      "createdAt": "2026-10-28T10:00:00Z"
    }
  ],
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 42,
    "totalPages": 3
  }
}

## 3. Ответ при ошибке валидации (400 Bad Request)
Структура JSON:
{
  "code": "VALIDATION_ERROR",
  "message": "Некорректные параметры запроса",
  "details": [
    {
      "field": "query",
      "message": "Строка поиска должна содержать от 2 символов"
    }
  ]
}

## 4. Граничные сценарии и поведение
- При отсутствии совпадений: 200 OK, data: [], meta.total: 0, meta.totalPages: 0.
- Очистка поисковой строки или смена фильтра: сбрасывает пагинацию на page=1.
- Серверная валидация: при нарушении типов или лимитов отдается статус 400 с детализацией по полям.
