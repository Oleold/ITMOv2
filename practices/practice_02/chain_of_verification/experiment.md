# Chain of Verification

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Проверяемый черновик или утверждение:
  Таблица unit‑проверок в `practices/practice_01/tests_unit.md` после Few‑shot и RCTF дополнений.

## Запрос на проверку

Применить Chain of Verification: пройдись по каждой строке таблицы unit‑проверок и сформулируй вопросы проверки, источники/шаги подтверждения и выяви несоответствия. Особое внимание:
- нет ли пересечений или противоречий между проверками пустого/слишком короткого diff;
- согласованы ли ожидания статусов (4xx/2xx) для лишних полей;
- не нарушают ли юнит‑проверки фактический код по TRAINING_PR.diff (например, сейчас /api/reviews не валидирует diff);
- нужны ли уточнения формулировок подтверждений для объективной проверки.

## Вопросы и результаты проверки

| Вопрос | Источник или проверка | Результат |
|---|---|---|
| Не конфликтуют ли проверки "Пустой diff" и "Минимальная длина diff"? | Сопоставление условий входа и ожидаемых результатов | Нет конфликта: пустая строка — отдельный кейс; минимальная длина — для непустых, но слишком коротких строк |
| Корректна ли политика для лишних полей в payload (2xx или 4xx)? | Текущий код API в TRAINING_PR.diff не валидирует схему | Разрешено принять 2xx и игнорировать лишние поля; корректируем формулировку на явное игнорирование |
| Соответствуют ли ожидания статусов фактическому коду? | TRAINING_PR.diff для /api/reviews | Фактический код бросает KeyError. Таблица задаёт целевое поведение API (4xx), это договор для будущей реализации. Оставляем как требование |
| Достаточно ли подтверждений для инварианта "LLM не вызывается при ошибке"? | Юнит‑подход с моками | Да: проверка счётчика вызовов мок‑объекта LLM.generate = 0 |
| Нужна ли точная минимальная длина diff? | Практика и здравый смысл | Уточним минимум как ≥5 символов для воспроизводимости |

## Исправленный результат

Скорректированы формулировки двух строк таблицы:
- "Лишние поля в payload" — уточнено: лишние поля игнорируются, статус 2xx, сервис работает предсказуемо;
- "Минимальная длина diff" — уточнено: минимум 5 символов.
