# R.C.T.F.

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- **Role:** Senior QA/AI Engineer, дополняющий unit‑проверки для сервиса ревью PR по diff
- **Context:**
  - В учебном PR (`TRAINING_PR.diff`) ручка `/api/reviews` падает с KeyError при отсутствии поля `diff`.
  - Уже добавлены проверки: отсутствие/пустой `diff`, ограничение размера, обработка ошибок парсинга LLM, схема ответа.
  - Цель: усилить негативные сценарии и формальную валидацию входа.
- **Task:**
  - Предложить и применить минимальные и проверяемые дополнения в `practices/practice_01/tests_unit.md`:
    1) валидация типа `diff` (должна быть строкой);
    2) валидация формата payload: отклонять лишние поля и неверные типы;
    3) запрет слишком короткого diff (например, < 5 символов) как бессмысленного ввода;
    4) явное требование, что при ошибках валидации LLM не вызывается.
- **Format:**
  - Вывести изменения в виде строк таблицы с полями: "Что проверяем изолированно", "Вход", "Ожидаемый результат", "Подтверждение". Изменения должны быть минимальными и непротиворечивыми ранее принятым правилам.

## Полный запрос


Применить R.C.T.F. для дополнения `practices/practice_01/tests_unit.md` новыми негативными unit‑проверками. Учитывай контекст учебного PR и уже принятые проверки. Добавь проверки на тип поля `diff` (только строка), формат payload (лишние поля/неверные типы), минимальную длину `diff` и гарантию, что при любой ошибке валидации LLM не вызывается. Верни в файл только конкретные строки таблицы и краткое пояснение в разделе "Как использовали AI". Сохрани текущую структуру файла.

## Что получили

Добавленные проверки в таблицу `tests_unit.md` для: нестрокового `diff`, лишних полей в payload, слишком короткого `diff`, и инварианта "при ошибке валидации LLM не вызывается".

## Что изменили в исходном артефакте

- Файл и раздел:
  - `practices/practice_01/tests_unit.md`, таблица Unit‑проверок
- Изменение:
  - 4 новые строки: тип `diff` — только str; формат payload — лишние поля игнорируются; минимальная длина `diff`=5; при ошибках валидации LLM не вызывается
- Как проверили:
  - просмотр diff; `make step2`
- Что отклонили:
  - Жёсткую схему payload с версионированием — избыточно для учебного кейса

## Оценка

Структурирование задачи через RCTF позволило четко очертить роль QA-инженера и добавить недостающие проверки устойчивости сервиса без усложнения кодовой базы. Оценка: 5/5, принято.
