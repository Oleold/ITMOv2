
# Few-shot

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Артефакт Практики 1: `practices/practice_01/tests_unit.md`
- Что хотим улучшить: добавить проверки граничных условий и багов по diff‑ревью — отсутствие поля `diff` (KeyError), пустой `diff`, ошибки парсинга ответа LLM и валидацию формата ответа, таймауты LLM

## Примеры

### Хороший результат

| Требование или правило | Что проверяем изолированно | Вход | Ожидаемый результат | Подтверждение |
|---|---|---|---|---|
| Валидация payload: поле diff обязательно | Обработчик API `/api/reviews` валидирует вход | `{}` | 4xx и понятная ошибка вместо KeyError | Юнит‑тест функции, проверяет отсутствие исключения KeyError и текст ошибки |
| Ограничение размера prompt | `ReviewService` усечёт слишком длинный diff | строка 10000 символов | Усечено до 8000 символов | Тест проверяет длину сформированного prompt |

### Плохой результат

| Требование или правило | Что проверяем изолированно | Вход | Ожидаемый результат | Подтверждение |
|---|---|---|---|---|
| Сервис что‑то возвращает | Любой вызов | "ok" | "ok" | Ручная проверка |
| Модель отвечает | Любой текст | "text" | "text" | Нет |

## Запрос

Используй технику Few‑shot: по двум примерам (выше) с хорошим и плохим оформлением таблицы юнит‑проверок дополни артефакт `practices/practice_01/tests_unit.md` недостающими тестами. Покрой:

- отсутствие поля `diff` и пустой `diff` для `/api/reviews`;
- граничное условие — слишком длинный `diff` (усечение в prompt);
- ошибки парсинга ответа LLM (невалидный JSON) и валидацию формата результата;
- таймауты внешнего вызова LLM (защитное поведение сервиса: понятная ошибка, отсутствие зависания);
- укажи, что именно проверяется изолировано, вход, ожидаемый результат и подтверждение.

## Что получили

Дополненные юнит‑проверки: добавлены строки на валидацию входа (`diff` отсутствует или пустой), ограничение размера `diff` в prompt, обработку ошибок парсинга ответа LLM и обязательные поля результата сервиса.

## Что изменили в исходном артефакте

- Файл и раздел:

  - введение ретраев при таймауте — отклонено как изменение логики; ограничились проверкой корректного возврата ошибки

## Оценка

Техника Few-shot позволила задать точную структуру таблицы и получить прикладные тесты для негативных сценариев вместо абстрактных проверок. Оценка: 5/5, принято.
